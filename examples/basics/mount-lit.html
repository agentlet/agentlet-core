Mount API: Lit

The core ships no UI framework of its own. Each agentlet mounts whatever it wants into the container the core hands it through mount(container, context). This example defines a Lit custom element and appends an instance of it in mount(), removing it in unmount().

What this example shows:

  • Defining a custom element (<agentlet-mount-demo>) with Lit, loaded as an ES module from a CDN
  • Appending/removing that element from mount()/unmount()
  • The element's own shadow root nesting inside the panel's shadow root without issue
  • Why that nested shadow root means the element must bring its own styles

Module source

// agentlet-mount-demo.js (loaded as an ES module)
import { LitElement, html, css } from 'https://cdn.jsdelivr.net/npm/lit@3/+esm';

class MountDemoElement extends LitElement {
    static properties = { count: { type: Number }, trigger: { type: String } };
    static styles = css`/* its own styles - nothing from the panel reaches in here */`;

    render() {
        return html`
            <div>Count: ${this.count}</div>
            <button @click=${() => this._change(1)}>+1</button>
            <button @click=${() => this._change('reset')}>Reset</button>
        `;
    }
    // ...dispatches a 'count-changed' event so the module stays the source of truth...
}
customElements.define('agentlet-mount-demo', MountDemoElement);

// The agentlet module itself
class MountLitModule extends window.agentlet.Module {
    constructor() {
        super({ name: 'mount-lit-demo', patterns: ['localhost'] });
        this.count = 0; // source of truth lives here, not in the element
        this.element = null;
    }

    async mount(container, context) {
        this.element = document.createElement('agentlet-mount-demo');
        this.element.count = this.count;
        this.element.trigger = context.trigger;
        this.element.addEventListener('count-changed', (e) => { this.count = e.detail.count; });
        container.appendChild(this.element);
    }

    async unmount(container) {
        this.element.remove();
        this.element = null;
    }
}

State retention and nested shadow roots

Clicking "Refresh panel content" calls window.agentlet.refreshContent(), which removes the custom element and appends a brand new instance with context.trigger === 'refresh'. A plain reactive property on that new instance would reset to its default. This example keeps this.count on the module instance instead, and the element reports changes back up through a count-changed event, so the count survives the same way it does in the vanilla and React examples.

<agentlet-mount-demo> attaches its own shadow root by default (that is how Lit's LitElement works), nested inside the panel's own shadow root. That nesting works without issue, but it also means the framework's .agentlet-btn button styling cannot reach across that second shadow boundary, so this element defines its own button styles in static styles instead of relying on it.
