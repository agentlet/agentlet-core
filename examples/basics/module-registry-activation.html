Module registry activation

This example demonstrates modules loaded from a registry script: seeing them through both window.agentlet.modules and window.agentlet.moduleRegistry, activating one by hand without it being reverted by automatic URL detection, and loading a lazy: true entry on demand.

What this example shows:

  • A module loaded from a registry script is visible from both window.agentlet.modules.get() and window.agentlet.moduleRegistry.get()
  • Activating a module by hand keeps it active, even while another module's pattern still matches the page
  • The active module survives single-page navigation (pushState, hash change) as long as it still matches the new URL
  • A lazy: true registry entry is listed but not fetched at init, and can be loaded on demand with loadModule() without being activated automatically

API examples:

// Registry entry declared with lazy: true is not fetched at init()
{ name: 'registry-module-c', url: '...', module: '...', lazy: true }

// Load it on demand, without activating it
const moduleC = await window.agentlet.moduleRegistry.loadModule({
    name: 'registry-module-c',
    url: './module-registry-activation-module-c.js',
    module: 'ModuleRegistryActivationModuleC'
});

// Activate it explicitly afterwards
await window.agentlet.moduleRegistry.activateModule(moduleC);
