Mount API: React

The core ships no UI framework of its own. Each agentlet mounts whatever it wants into the container the core hands it through mount(container, context). This example creates a React 18 root in mount() and tears it down in unmount(), with no build step: React.createElement instead of JSX.

What this example shows:

  • Creating a ReactDOM.createRoot(container) in mount() and rendering into it
  • Calling this.root.unmount() in unmount() and clearing this.root
  • Why React's own component state does not survive a remount, and how to work around it
  • Reading context.trigger to show why the last mount happened

Module source

class MountReactModule extends window.agentlet.Module {
    constructor() {
        super({
            name: 'mount-react-demo',
            patterns: ['localhost'],
            description: 'Mount API demo built with React 18'
        });
        this.count = 0; // source of truth lives here, not in React state
        this.root = null;
    }

    async mount(container, context) {
        if (!this.root) {
            this.root = ReactDOM.createRoot(container);
        }
        this._render(context.trigger);
    }

    _render(trigger) {
        const e = React.createElement;
        this.root.render(e(Counter, {
            count: this.count,
            trigger,
            onIncrement: () => { this.count++; this._render(trigger); },
            onReset: () => { this.count = 0; this._render(trigger); }
        }));
    }

    async unmount(container) {
        if (this.root) {
            this.root.unmount();
            this.root = null;
        }
    }
}

State retention

Clicking "Refresh panel content" calls window.agentlet.refreshContent(), which unmounts the React root and mounts a brand new one with context.trigger === 'refresh'. A plain useState counter inside the React component would reset to zero on that new root. This example avoids that by keeping this.count on the module instance and passing it into the component as a prop on every render, so the count survives the remount the same way it does in the vanilla example: it never actually lived in React.
